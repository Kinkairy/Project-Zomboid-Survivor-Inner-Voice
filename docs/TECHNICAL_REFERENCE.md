# Survivor Inner Voice 0.3.3 技术参考

本文档描述当前公开 Workshop 版本 `0.3.3`。适用范围：Project Zomboid
Build 42.20，Workshop `3793128772`，Mod ID `SurvivorInnerVoice`，无外部依赖。

## 1. 设计边界

本项目只负责把角色能够直接感知的当前状态转换为短促、可读的头顶自言自语。它不改变状态
数值、角色属性、物品、动作、世界、僵尸感知或存档数据，也不把隐藏感染作为提示来源。

优先复用原版已有语义与表现接口：

- 正式 moodle 的标题和说明通过游戏翻译 key 在运行时解析，不复制成第二份自定义文本；
- 颜色复用玩家当前的原版正面与负面高亮色，并使用原版灰色到高亮色的等级插值；
- 原版提示和原创心声均使用角色的原版 `setHaloNote`；系统提示以灰色 `<内容>` 表示且不带图标，
  原创心声以严重度颜色和句末 Moodle 图标区分；
- 角色心声字体可选原版 `Small / Medium / Large / Massive`，默认 `Medium`；原版提示固定为
  `Small`，并可由默认开启的官方布尔沙盒选项整体隐藏；
- 原创心声的状态图标通过 halo-note 的原版 `TextDrawObject` 支持的 `[img=…]` 标记引用 B42
  自带 Moodle 纹理，不复制图片也不建立自定义渲染器；
- Build 42.20 的正式 `MoodleType` 和 `CharacterStat` 枚举是状态读取边界。

自建逻辑只包括原版没有的状态目录、双向台词 key、随机调度、最近台词避重、变化队列、
初始静默和可选语义事件验证。

## 2. 模块职责

| 模块 | 职责 |
| --- | --- |
| `SIV_Catalog.lua` | 唯一状态表、等级归一化、稳定 key、原版槽位分类、官方 Moodle 图标路径、颜色插值与协议 allowlist |
| `SIV_Scheduler.lua` | 状态快照比较、升降队列、优先级、随机截止时间、提醒与最近台词避重 |
| `SIV_Client.lua` | 一秒节流取样、沙盒频率映射、原版颜色读取与本地头顶渲染 |
| `SIV_Server.lua` | 可选 `spoken` 语义事件的发送者身份、参数验证、三秒限流与广播 |
| `Translate/CN・CH・EN` | 自定义台词和沙盒界面翻译，三语使用同一稳定 key 集合 |

客户端和服务器都引用同一 `SIV_Catalog.lua`，因此状态、可达等级、台词序号和协议合法性没有
第二套平行定义。

## 3. 状态目录与可达等级

目录包含 26 个定义：25 个负面状态和正面 `FoodEaten`。其中：

- `on_fire` 只允许四级；
- `cant_sprint` 只允许原版实际存在的一级；
- 其余 24 个定义允许一级到四级；
- 总计恰好 98 个实际可达的“状态 × 等级”组。

正式 moodle 包括出血、受伤、疼痛、生病、恐慌、失温、过热、风寒、感冒、疲劳、无法冲刺、
耐力、口渴、饥饿、负重、吃饱、潮湿、恶臭、醉酒、压力、愤怒、不适、不开心和无聊。
`nicotine` 从 `NICOTINE_WITHDRAWAL` 角色统计读取，`on_fire` 从当前身体伤害标记读取。

目录按危险性提供稳定优先级。同一扫描有多个候选时，先比较优先级，再比较创建时间和队列序号。
未识别状态安全地归零，不会中断其他状态扫描。

## 4. 台词模型

每个可达组在两个方向各有 8 个逻辑位置：

- `rise`：从无到有、状态加重，或严重状态定时提醒；
- `fall`：状态减轻，`toLevel=0` 表示完全恢复。

98 组 × 2 个方向 × 8 个位置，共 1568 个逻辑台词槽位。其中 191 个 `rise` 槽位直接解析
原版文本：93 个正式 moodle 组各使用标题和说明两个槽位，着火使用一个原版标签槽位，烟瘾
四级各使用一个原版标签槽位。目录用同一组状态、方向和序号规则把这 191 个槽位标记为
`vanilla`，剩余 1377 个三语自定义槽位标记为 `thought`，不会根据文本内容猜测类型。

自定义 key 格式为：

```text
IGUI_SIV_<state>_<RISE|FALL>_L<phraseLevel>_<01..08>
```

下降事件的 `phraseLevel` 使用变化前等级，`toLevel` 记录变化后的剩余等级。这样同一组台词既
能准确表达“从三级缓到二级”，也能把“从一级完全恢复”与仍有残余的不适区分开。

简中语料要求：不使用“状态降级、恢复正常、问题消失”等系统播报；出现或加重必须让人从句子
本身听出严重程度；部分恢复同时表达好转和残余；通用不适必须包含明确身体锚点，但不能虚构
骨折、内伤、中毒、感染或具体疾病。隐藏感染相关 key 和状态均不存在。

## 5. 调度器

`SIV.Scheduler` 是不读取游戏对象的纯状态机。客户端每秒构造一次状态快照并调用 `scan`。
首次扫描只初始化状态和随机静默截止时间，不立即显示台词。

沙盒暴露 `Frequency` 五值枚举、`FontSize` 四值枚举和默认开启的布尔值
`ShowVanillaPrompts`。`FontSize` 只控制角色心声，依次为原版
`Small / Medium / Large / Massive`，默认值 2，即 `Medium`。原版状态提示固定使用 `Small`。
关闭 `ShowVanillaPrompts` 时，调度器在最近记录和最久未用候选计算前排除 `vanilla` 槽位，
因此不会产生空白触发，也不改变心声频率、冷却或队列语义。频率映射如下：

| 值 | 显示 | 平均全局间隔 | 同状态间隔 | 严重状态提醒 |
| --- | --- | ---: | ---: | ---: |
| 1 | 很少 / Very Rare | 60 秒 | 540 秒 | 1800 秒 |
| 2 | 较少 / Rare | 35 秒 | 315 秒 | 1050 秒 |
| 3 | 普通 / Normal | 20 秒 | 180 秒 | 600 秒 |
| 4 | 频繁 / Frequent | 12 秒 | 108 秒 | 360 秒 |
| 5 | 很频繁 / Very Frequent | 6 秒 | 54 秒 | 180 秒 |

初始静默、全局间隔、同状态间隔和提醒间隔都在基准值的 70%–130% 之间一次性抽取实际截止
时间。最低全局安全间隔固定为 3 秒；四级恶化仍可绕过普通全局截止时间，但不能绕过该安全
间隔。

普通档位在同一状态继续变化时移除旧等待项，只保留最新变化。“很频繁”使用 `queueEveryChange`
保留每次升降过程，并按优先级和创建顺序逐条输出。三级或四级状态在没有继续变化时，也可以在
提醒截止时间到达后形成候选。

台词选择先排除最近 8 个 key，再从最久未使用的候选中随机选择；如果同组可用项已经耗尽，
则复用全局最久未出现的项。随机只决定等价候选和截止时间，不改变状态优先级或语义等级。

## 6. 颜色与显示

原版槽位通过角色的 `setHaloNote` 进入游戏自己的头顶提示层，使用灰色
`RGB(170,170,170)`，显示为 `<内容>`，不带图标、括号、升降箭头或斜体。正文固定使用原版
`Small` 字体，不受角色心声字体选项影响。
每次仍只显示当前 scheduler 选中的一条，不会在同一个事件里额外追加原创台词。

原创心声同样通过角色的原版 `setHaloNote` 显示，不加括号。正式 Moodle 对应的角色台词会在
正文的字体段结束后保留两个空格，再追加 `[img=media/ui/Moodles/48/<官方文件名>]`，让图片
标签单独解析并与正文保持可见间距；该
通道的原版文本对象启用了任意图片路径。
角色聊天通道虽然解析 `[img=…]`，但只允许四个硬编码图片名或物品图标，不能显示 Moodle
完整路径。Mod 不包含图片副本；`FoodEaten` 与原版一样复用饥饿图标。着火和尼古丁戒断不是
`MoodleType`，正式服没有对应 Moodle 图标，因此保持纯文字，不以自创图标代替。
客户端运行时读取：

```text
Core.getBadHighlitedColor()
Core.getGoodHighlitedColor()
```

每个颜色分量从原版灰色 `0.5` 按 `level / 4` 插值到当前高亮色：

```text
component = 0.5 + (highlight - 0.5) * (level / 4)
```

负面状态使用到达等级的负面色；正面状态使用到达等级的正面色；负面状态完全恢复时使用一级
正面浅色。渲染参数来自 scheduler 的 `stateId`、`direction` 和 `toLevel`，颜色不会依赖台词
字符串或客户端可伪造的外部字段。

可选的 `spoken` 广播继续作为角色台词显示，不加括号，并复用同一官方 Moodle 图标后缀；它
不会因为对应 key 来自原版而改走系统提示。默认本地调度器不会自动发送它。

## 7. 客户端与多人协议

客户端通过弱引用表为每个本地玩家保存独立 scheduler；角色创建时清空旧运行态。死亡角色不再
扫描。状态只来自当前本地玩家对象，不写入 `modData`。

默认路径直接在本地显示心声。服务器模块只为显式的 `spoken` 事件提供受限协议：

1. 只接受模块名和命令均正确的事件；
2. `stateId`、`direction`、`phraseLevel`、`toLevel`、`phraseIndex` 必须组成目录中真实存在的
   语义事件；
3. 服务器忽略客户端提供的原始文本、颜色、音量和 online ID；
4. online ID 从真实发送者取得；
5. 每名发送者至少间隔 3 秒；
6. 下行仍只携带语义字段，客户端用本地目录重建翻译 key 和颜色。

该协议只保护表现事件的结构和身份，不把客户端报告的 moodle 当作服务器权威玩法事实。由于
默认心声不改变世界，该边界是有意设计；如果未来台词会影响 AI、声音或玩法，必须先重新设计
服务器权威状态验证。

## 8. 本地化

CN、CH、EN 的自定义 key 集合完全一致。原版槽位通过 `getText` 读取当前游戏语言，因此 Mod
不会维护原版标题和说明的重复翻译。找不到翻译时，客户端拒绝显示原始 key。原版和原创分类
由目录元数据决定，不依赖本地化后的字符串，因此切换语言不会改变显示通道。

沙盒翻译使用 Build 42.20 的 `Translate/<locale>/Sandbox.json`；运行代码不包含玩家可见的
硬编码台词。新增状态、等级或方向时，必须同时更新三语 key、目录 allowlist 和调度测试。

## 9. 持久化与兼容边界

- 不调用 `getModData`，不写角色、物品或世界存档字段；
- 不调用 `addSound`，不会因为心声吸引僵尸；
- 不使用 `processSayMessage`，默认心声不是普通聊天；
- 无外部依赖，可加入现有存档；移除后不需要数据迁移；
- 当前只保证 Project Zomboid Build 42.20；游戏更新正式枚举、翻译 key 或渲染接口后必须重新
  审计，不能根据旧版本猜测。
